# Что изменено в этом форке и что осталось рискованным

База: NextStat/yacli 0.5.5, коммит `7a44002`. Форк не связан с автором оригинала и не поддерживается им. Ветка `hardened`.

## Изменения по сравнению с оригиналом
| Было | Стало |
|---|---|
| Самообновление (`update`, скачивает бинарник с GitHub, проверка SHA256 из того же релиза), скрипты `install.sh` / `install.ps1` | Удалено. Сборка только из исходников. |
| `mcp install` правил конфиги 9 клиентов и писал «skills» в каталоги агентов | Удалено. Подключение вручную (см. навык). |
| Хосты OAuth, IMAP, SMTP, CalDAV, Диска можно задать через конфиг и переменные окружения | Белый список хостов Яндекса, только HTTPS, фиксированные порты; переопределения только в debug-сборке (`src/net_policy.rs`). |
| Редиректы клиентов CalDAV и Диска без проверки | Каждый переход проверяется (https, хост из списка, без userinfo, не более 5). |
| Секреты могли лежать в `credentials.toml` открытым текстом | В release только системное хранилище; `YACLI_SECRET_BACKEND=file` отклоняется. |
| PKCE `code_verifier` в `oauth_sessions.toml` | В системном хранилище, уникальный ID сессии, блокировка, стирается после обмена и по TTL. |
| HTTP-режим MCP слушал любой адрес, токен необязателен | Только loopback, проверка Host, токен (если задан) сравнивается за постоянное время и требуется для всех вызовов инструментов и ресурсов. |
| Вход в почту только OAuth | Добавлен вход по паролю приложения: `auth login --service mail`, `account set-mail-auth`. |
| `Message-ID` и SMTP `EHLO` содержали домен автора оригинала | Домен отправителя и `localhost`. |
| Журнал действий (`activity.toml`) хранил получателей, темы, имена файлов, пути Диска и публичные ссылки | Только нейтральная сводка и шаблон команды без значений; для отката остаётся технический идентификатор (UID события, путь ресурса); очистка: `yacli activity clear --yes`. |
| Известные уязвимости зависимостей (rustls, h2, quick-xml, quinn-proto, tar и др.) | Обновлены; `cargo audit` и `cargo deny` без замечаний на момент сборки. |
| Релизные workflow и Homebrew/winget для бинарников автора | Workflow удалён. Файлы `Formula/` и `scripts/generate-*` остались и не используются; не запускай их. |

Функции почты, календаря и Диска (чтение, отправка, ответ, пересылка, вложения, события, файлы) сохранены.

Добавлено управление письмами: `mail mark`, `mail move`, `mail trash` (CLI и MCP, с `dry_run`, нейтральной записью в журнале). Безвозвратное удаление намеренно не реализовано.

## Что остаётся рискованным
- **Широкие права.** Пароль приложения «Почта» даёт полный доступ к ящику (чтение, отправка, удаление), как и OAuth-скоупы `mail:imap_full` + `mail:smtp`. Ограничить это в Яндексе нельзя; только правила разрешений клиента.
- **Prompt injection из писем.** Любой почтовый MCP читает недоверенный текст. Защита: правила `ask` на всё, что пишет или отправляет (см. навык).
- **Сервер не ограничивает набор инструментов.** Запрет опасных действий держится только на правилах разрешений клиента (`ask`). Сервер выполнит любой свой инструмент, если клиент его вызвал и разрешение получено или не требуется. Для личного использования это сознательный выбор: полный набор функций, как у Gmail-коннектора. Если форк будет использовать кто-то ещё (общий компьютер, несколько людей, автоматизация без человека), добавьте на стороне сервера список разрешённых инструментов и отдельные права на чтение, отправку и запись; в этом форке этого нет.
- **Авто-режим клиента.** Если он включён, отправку может одобрить классификатор без вас. Нужны явные правила `ask`.
- **Аудит неполный.** Прочитаны критичные файлы (OAuth, хранилище, обновление, установка, сеть) и независимо проверены вторым ревьюером. Зависимости (~300 крейтов) и готовые бинарники автора не проверялись.
- **Debug-сборка слабее release.** Для настоящего аккаунта используй только `cargo build --release`.
- **Права файлов на Windows** не ужесточаются явно (ACL наследуются от каталога).
- **Тесты.** На Windows часть тестов падает по причинам, не связанным с безопасностью: ожидание `yacli` вместо `yacli.exe` в справке, CRLF в рабочей копии, общее окружение в тестах.
